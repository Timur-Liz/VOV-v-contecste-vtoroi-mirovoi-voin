# Великая Отечественная война в контексте Второй мировой войны

Образовательный сайт по разделу III «БССР в годы Второй мировой и Великой Отечественной войн»
учебного пособия «История Беларуси, 1917 г. — начало XXI в.» (9 класс, § 11–16).

**Хаб** (главная страница) + **8 тем**, в каждой: интерактивная карта, хронология, конспект,
личности с портретами, галерея фото и документов, викторина.

---

## ▶ Как открыть сайт

**Дважды щёлкните по файлу `index.html`** в папке проекта — сайт откроется в браузере.

Больше ничего не нужно: ни терминала, ни установки, ни сервера. Сайт сделан на чистом
HTML + CSS + JavaScript и работает прямо из папки, в том числе без интернета
(без интернета не загрузятся только шрифты Google и онлайн-подложка карты — вместо неё
показывается встроенная схема Беларуси).

В VS Code: откройте папку проекта → `index.html` → правой кнопкой **Open with Live Server**
(или кнопка **Go Live** внизу справа). Либо `Run → Start Debugging` → «Открыть сайт (index.html) в Chrome».

> Важно: папки `assets`, `topics` и `public` должны лежать **рядом** с `index.html`.
> Если скопировать один только `index.html`, страница откроется без оформления.

## 🌐 Публикация на GitHub Pages

Сборка не нужна — GitHub просто раздаёт файлы из репозитория.

### Шаг 1. Загрузить проект в репозиторий

**Вариант А — GitHub Desktop (проще всего).** Установите [GitHub Desktop](https://desktop.github.com),
`File → Add local repository` → выберите папку проекта → «create a repository» → `Publish repository`
(снимите галочку «Keep this code private»).

**Вариант Б — терминал VS Code:**

```bash
git init
git add .
git commit -m "Сайт по истории ВОВ в Беларуси"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

**Вариант В — через браузер.** На странице репозитория: `Add file → Upload files` и перетащите
файлы. GitHub принимает не больше 100 файлов за раз, поэтому загружайте по папкам. Для работы
сайта достаточно этого набора (92 файла):

```
index.html   404.html   .nojekyll
assets/        ← стили, скрипты, данные тем
topics/        ← страницы тем
public/images/ ← все картинки
```

### Шаг 2. Включить Pages

В репозитории: **Settings → Pages → Build and deployment**

- **Source:** `Deploy from a branch`
- **Branch:** `main`, папка `/ (root)` → **Save**

Через 1–2 минуты сайт будет доступен по адресу
`https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПОЗИТОРИЯ/`.

Имя репозитория может быть любым: все ссылки и пути на сайте относительные.
Секреты в репозиторий не попадут — файл `.env` указан в `.gitignore`.

### Что умеет сайт

- **Хаб:** карточки тем, поиск, фильтр по тегам, прогресс «изучено тем: X из 8».
- **Карта** (Leaflet): точки событий со справками, линии фронта, встроенная схема Беларуси
  (работает офлайн), онлайн-карта по кнопке. На телефоне карта двигается двумя пальцами.
- **Хронология:** кнопка «На карте» показывает место события.
- **Конспект:** три объёма — кратко / средне / подробно, кнопки «Сократить» и «Расширить»,
  копирование. В этой версии показываются заранее подготовленные конспекты (без запросов к ИИ).
- **Викторина:** 8–9 вопросов, проверка, объяснения, баллы, разбор ошибок.
- **Галерея** с просмотром во весь экран, **личности** с портретами.
- Светлая и тёмная тема, адаптивная вёрстка (телефон, планшет, десктоп).
- Прогресс и результаты викторин сохраняются в браузере (localStorage).

## ✏️ Как изменить содержание

**Быстрые правки — прямо в готовых файлах** (обновите страницу в браузере, и всё):

- текст на странице — в `index.html` или `topics/<тема>/index.html`;
- вопросы викторины, конспект, точки карты — в `assets/data/topic-XX-….js`;
- оформление — в `assets/css/site.css`, поведение — в `assets/js/site.js`.

**Правильный способ — править исходные данные и пересобрать сайт** (иначе при следующей
сборке ручные правки в готовых файлах затрутся). Нужен [Node.js 20+](https://nodejs.org):

```bash
npm install          # один раз
npm run build:html   # пересобирает index.html, topics/ и assets/ из исходников
```

Исходники:

- `src/data/topics/topic-0X-*.ts` — содержание каждой темы (текст, карта, хронология, конспект,
  личности, галерея, викторина). Новая тема = новый файл + строка в `src/data/topics/index.ts`.
- `src/data/photos.ts` — какие фото и портреты показывать; `npm run images:fix` проверяет файлы
  и докачивает недостающие с Wikimedia Commons.
- `src/app/globals.css` — стили; `src/components/` — разметка блоков.
- `assets/js/site.js` — интерактив автономного сайта (этот файл не генерируется, правится вручную).

## 🛠 Если что-то не работает

| Что видно | Причина и решение |
|-----------|-------------------|
| Страница без оформления, вверху рамка «Стили сайта не загрузились» | Рядом с `index.html` нет папки `assets`. Скопируйте / загрузите проект целиком. |
| Нет картинок | Нет папки `public/images` или файлы повреждены. При наличии интернета сайт сам подгрузит фото с Wikimedia Commons; локально поможет `npm run images:fix`. |
| На GitHub Pages вместо сайта текст README | В Settings → Pages выбрана не та папка или в репозитории нет `index.html` в корне. Нужно: `Deploy from a branch` → `main` → `/ (root)`. |
| На GitHub Pages ошибка 404 | Подождите 1–2 минуты после включения Pages; проверьте, что репозиторий публичный и адрес заканчивается на `/ИМЯ_РЕПОЗИТОРИЯ/`. |
| Карта пустая | Не загрузился `assets/vendor/leaflet.js` или `assets/data/geo.js` — проверьте, что папка `assets` загружена полностью. |
| Не сохраняется прогресс | Браузер в режиме инкогнито или запрещены данные сайтов — прогресс хранится в localStorage. |

## Для разработчиков: полный режим (необязательно)

Тот же сайт существует как приложение Next.js — с сервером, базой данных и генерацией
конспектов через ИИ. Для просмотра и публикации это **не требуется**.

```bash
npm install
npm run dev               # http://localhost:3000 — разработка с «горячей» перезагрузкой
```

База данных не обязательна: без неё серверные функции мягко отключаются. Полный режим:

```bash
cp .env.example .env      # DATABASE_URL (PostgreSQL) и при желании OPENAI_API_KEY
npm run db:push           # создаёт таблицы
npm run dev
```

- **PostgreSQL + Drizzle** — результаты викторин всех учеников, синхронизация прогресса, кэш конспектов.
- **Конспект через ИИ** — при заданном `OPENAI_API_KEY` маршрут `/api/summary` отправляет текст темы
  в модель (`OPENAI_MODEL`, по умолчанию `gpt-4o-mini`; `OPENAI_BASE_URL` — для совместимых
  провайдеров). Ключ хранится только на сервере. Без ключа показывается подготовленный конспект.
- Развёртывание полного режима — любой Node.js-хостинг (например, Vercel + Neon/Supabase).

| Команда | Назначение |
|---------|-----------|
| `npm run build:html` | пересобрать автономный сайт в корне проекта (index.html, topics/, assets/) |
| `npm run images:fix` | проверить картинки и докачать недостающие |
| `npm run dev` | сервер разработки Next.js |
| `npm run build` / `npm start` | production-сборка и запуск полного режима |
| `npm run build:static` / `npm run preview:static` | статический экспорт Next.js в `out/` и его просмотр |
| `npm run db:push` | создать таблицы в PostgreSQL |
| `npm run typecheck` / `npm run lint` | проверка типов / линтер |

Как устроена сборка автономной версии: `scripts/build-html.mjs` берёт готовую разметку из
статического экспорта Next.js, убирает из неё всё, что требует сервера (скрипты Next.js,
абсолютные пути), складывает стили в один файл, копирует Leaflet, выгружает данные тем в
`assets/data/` и подключает `assets/js/site.js`.

## Источники

Содержание тем соответствует учебному пособию «История Беларуси, 1917 г. — начало XXI в.»
(9 класс; С. В. Панов, В. Н. Сидорцов, В. М. Фомин), раздел III, § 11–16.

Изображения, подписанные как «художественная реконструкция», созданы специально для сайта
в учебных целях. Исторические фотографии и портреты — Wikimedia Commons (авторы и лицензии
указаны в подписях и в `src/data/photo-manifest.json`); современные фото мемориалов —
Wikimedia Commons и Pexels. Границы — geoBoundaries (CC BY 4.0), реки — Natural Earth
(общественное достояние). Карты — Leaflet (BSD-2), онлайн-подложка — © участники OpenStreetMap.
